Workflow: make a blank Google Sheet (or reuse one), paste its link above, press ⬆ Update Google Sheet — the sheet gets the input-list template (show info, #/CH NAME/M·L·R dropdown/MIC/STAND/POSITION/NOTES) filled with the builder's current inputs. Edit the sheet, press ⬇ Update Builder to pull it back: a stereo channel is an L row followed by an R row; routing, links and racks set in the builder are kept for channels with the same name.
Note: the standalone app file (opened in Chrome/Edge/Safari) syncs with Google directly. On claude.ai the page can't call Google itself, so there the sync runs through the Claude desktop app's built-in browser (open the builder in the desktop app; it asks once for permission and its Browser pane briefly shows the bridge responses). If you update the bridge script, redeploy it: Deploy → Manage deployments → ✎ → Version: New version → Deploy (the /exec URL stays the same).

The exported .json is the LV1 conversion spec: feed it to make_lv1_session.py --spec to generate the .emo (the show name becomes the file name). Only named strips are built, packed top-down; the vendor PDF carries only #, name, format, mic, stand and stage position for named inputs — no routing or racks. The mixer configuration is recorded in the spec; the converter needs a factory template of the same configuration (the 80-input / 16-group one is built in). Racks: each strip's rack is 8 slots (0–7), exactly like LV1. The default EMO-F2 / EMO-D5 / EMO-Q4 are ordinary rack plugins — delete, reorder (drag or ↑↓) or re-add them like anything else. The searchable picker lists only SoundGrid-compatible plugins (those shipping SoundGrid-server process code) scanned off this machine's Plug-Ins V16/V17 bundles — the same set LV1's own menus show. Plugins load with their factory default preset. “Stock” racks (F2 → D5 → Q4) export no rack field.
